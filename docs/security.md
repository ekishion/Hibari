# 安全模型

本文描述服务实际实现的防护措施，以及明确不做的部分。后者同样重要——知道自己不受什么保护，才能正确部署。

## 认证

### 单一机制

只有一套认证：登录成功后服务端下发不透明会话令牌，浏览器把它存在 HttpOnly Cookie 里。

没有 JWT，没有双令牌轮转，没有「只读令牌」，也没有在配置文件里写死的静态访问令牌——这些机制都会扩大攻击面而收益有限。

### 会话令牌

- 32 字节密码学随机数，十六进制编码。
- 服务端只存 SHA-256 摘要。数据库泄露不会直接得到可用令牌。
- 令牌熵足够高，不需要加盐或慢哈希——慢哈希是为了抵御对低熵口令的猜测，对随机令牌没有意义。
- 有效期由 `session_ttl_seconds` 控制，默认 7 天。过期记录每小时清理一次。
- 修改密码会吊销该用户的全部会话。
- 退出登录删除服务端记录，令牌立即失效，不是等过期。

### Cookie 属性

| 属性 | 值 | 作用 |
| --- | --- | --- |
| `HttpOnly` | 是 | JavaScript 读不到，XSS 无法直接窃取令牌 |
| `SameSite` | `Lax` | 跨站请求不携带，阻断大部分 CSRF |
| `Secure` | TLS 时自动 | 明文连接下不发送 |
| `Path` | `/` | — |

`secure_cookie` 配置项可强制开启 `Secure`，用于 TLS 在代理终止的场景——此时服务端看不到 TLS，无法自动判断。

### 密码

Argon2id，参数取 OWASP 推荐值：

| 参数 | 值 |
| --- | --- |
| 内存 | 64 MiB |
| 迭代 | 3 |
| 并行度 | 2 |
| 盐 | 16 字节随机 |
| 输出 | 32 字节 |

存储格式是标准 PHC 串（`$argon2id$v=19$m=65536,t=3,p=2$...`），参数随散列一起保存，将来调整参数不需要迁移数据。

密码长度限制 8–128 字符。128 是上限，防止超长输入消耗内存。

### 登录失败处理

用户名不存在与密码错误返回同一个错误，不泄露账号是否存在。失败响应延迟 300 ms，抬高暴力破解成本。

此外所有接口都有按 IP 的令牌桶限流，默认每秒 10 次、突发 20 次。

来源 IP 的判定是一条信任链：直连地址不在 `trusted_proxies` 内时一律用直连地址，忽略全部转发头。只有在可信代理后面才读 `X-Forwarded-For`，并且**从右往左**跳过可信代理，取第一个不可信地址。左侧元素由客户端可伪造，取首元素等于让人随手换 IP 绕过限流。链上出现非法值或某跳不可解析时，回落到直连地址。

## 授权

### 角色

只有一种角色：管理员。访客不进入角色体系，通过分享链接访问，权限由链接本身携带。

这是有意的范围限制。多用户、权限组、只读账号都没有实现。

### 路径白名单

`allowed_paths` 限定可浏览与可写入的子树。空白名单表示不限制。

根目录 `/` 始终放行——它是挂载容器，本身不含内容。列出根目录时逐项过滤，白名单外的条目不会出现在结果里。

### 符号链接

本地后端的边界由内核提供，而不是手写路径比较：`New` 用 `os.OpenRoot` 打开存储根目录，之后每次 `Stat`、`Open`、`Put`、`List`、`Remove` 都在这个 `*os.Root` 上执行。任何解析到根目录之外的路径（符号链接、`..`、绝对路径）都会由内核拒绝，返回 `path escapes from parent`。

这是刻意的选择。早先的实现用 `filepath.EvalSymlinks` 复核真实路径，在 Linux 上够用，但在 Windows 上并不解析目录联接（junction）——一个 `mklink /J` 就能让 `Open`、`Stat`、`Put` 全部穿透到外部目录。`os.Root` 没有这个缺口，且不受 TOCTOU 竞态影响。

`os.Root` 的额外约束：根目录内的符号链接必须是**相对**的，绝对链接一律被拒。这不影响正常使用——`List` 会跳过符号链接与联接条目，用户看不到点不动的项；删除时 `Root.RemoveAll` 只删链接本身，不会递归删掉它指向的外部目录。

`os` 包没有导出越界错误的哨兵值，`translate` 按错误文本匹配，`TestTranslateEscape` 会在 Go 改动这段文案时失败报警。

### 分享沙盒

目录分享访问者被圈定在分享根目录内：

1. 请求路径先经 `library.CleanPath` 规范化，拒绝 `.`、`..` 段和控制字符。
2. 相对路径与分享根目录拼接。由于上一步已排除 `..`，`path.Join` 不会逃逸。
3. 拼接结果再用 `library.IsUnder` 复核一次，纵深防御。
4. 最后过一遍 `allowed_paths` 白名单。

返回给访客的路径会重写为相对分享根的路径，服务器真实目录结构不会泄露。

文件分享更严格：只有被分享的那个文件本身可访问，其它路径一律 `403`。单文件分享的下载入口在发出内容前还会按当前 `allowed_paths` 复核一次——配置可能在分享创建之后收窄。

### 提取码

- 由服务端生成，或由创建者指定。
- 存储时用 SHA-256 加盐散列，盐是分享令牌本身——同一提取码在不同分享中散列不同，无法通过比对数据库发现复用。
- 校验用恒定时间比较。
- 提取码错误不消耗使用次数。
- 未解锁时不返回文件名、类型、过期时间，只能知道「这个链接需要提取码」。

### 使用次数

`max_uses` 限制下载次数。扣减在单条 SQL 中完成：

```sql
UPDATE shares SET uses = uses + 1
WHERE token = ? AND (max_uses = 0 OR uses < max_uses)
```

先读后写会产生竞态——两个并发请求都读到 `uses=0`，都判断通过，最终超发。单条条件更新由数据库保证原子性。

计次时机同样重要。`Resolve` 只做校验、不改状态，扣减由调用方在所有校验通过后显式调用 `Consume`。这样被拒绝的请求（提取码错误、目录分享走错入口、路径越界）不会白烧次数。

计次的只有真实下载：单文件下载与 `raw?download=1`。目录浏览与内联预览不计次——视频预览会发出多次 `Range` 请求，计次会让一次播放就耗尽配额。

## CSRF

用 `Origin` 头校验，不引入 token。

非 `GET`/`HEAD`/`OPTIONS` 的请求，若带 `Origin` 头且其主机与 `Host` 不一致，返回 `403`。

浏览器对跨站 POST 一定带 `Origin`，所以跨站请求会被拦下。不带 `Origin` 的请求来自非浏览器客户端（curl、服务端调用），这类客户端本来就不受 CSRF 影响，放行。

配合 `SameSite=Lax` Cookie，形成两层防护。

## 响应头

所有响应都带：

| 头 | 值 |
| --- | --- |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `DENY` |
| `Referrer-Policy` | `no-referrer` |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` |
| `Content-Security-Policy` | 见下 |

```
default-src 'self';
img-src 'self' data: blob:;
media-src 'self' blob: https://*.baidu.com https://*.baidupcs.com https://*.bdstatic.com;
style-src 'self' 'unsafe-inline';
frame-ancestors 'none'; object-src 'none'; base-uri 'none'; form-action 'self'
```

`media-src` 放行百度域名是给百度后端用的——直链播放时浏览器会直接连上游。`style-src` 需要 `unsafe-inline`，因为 Vue 会写内联样式属性。

`frame-ancestors 'none'` 与 `X-Frame-Options: DENY` 重复，前者是新标准，后者兼容老浏览器。

## 上传

- 大小限制由 `upload_max_mb` 决定，超限返回 `413`。
- 先写临时文件，完整写入并校验字节数后才原子重命名。中断不会留下半个文件，也不会覆盖已有文件。
- 文件名拒绝 `/`、`\`、控制字符，无法通过文件名构造路径。

## 上游凭据

百度后端需要用户的 Cookie。这份凭据的处理：

- 只存在于服务端配置，任何接口都不返回它。
- 列表接口的响应结构里根本没有 `dlink` 字段，结构上不可能泄露带凭据的下载地址。有测试断言序列化后的 JSON 不含该字段。
- 换取直链后校验协议必须是 `https`，主机必须是 `baidu.com` / `baidupcs.com` / `bdstatic.com` 或其子域，防止上游被劫持后变成开放重定向。
- `baidu_base_url` 必须是 https，只有回环地址允许 http（供本地测试）。用 http 传 Cookie 等于明文泄露。

## 审计

记录 `setup`、`login`、`password.change`、`mkdir`、`rename`、`remove`、`move`、`copy`、`upload`、`share.create`、`share.revoke`、`share.download`、`share.browse`。

- IP 掩码后存储：IPv4 末段替换为 `x`，IPv6 保留前 48 位。
- User-Agent 截断到 256 字节。
- 保留 30 天，每小时清理一次。
- 写审计失败只记警告，不影响主流程。

审计日志不是防篡改的。有数据库写权限的人可以修改它。

## 传输

服务本身不终止 TLS，也不强制跳转 https。TLS 应在反向代理层完成，见 [deployment.md](deployment.md)。

在代理终止 TLS 时：

- 配置 `secure_cookie: true`，否则 Cookie 会走明文。
- 配置 `trusted_proxies`，否则限流把所有请求算作代理 IP，审计日志里的来源也失去意义。

直接用 http 对外提供服务等于所有会话令牌明文传输。除了本机访问，不要这样做。

## 明确不做

| 不做 | 原因 |
| --- | --- |
| 多用户与权限体系 | 产品定位是个人或小团队的单管理员实例 |
| 二步验证 | 单管理员场景下，网络层访问控制更有效 |
| 加密存储文件 | 服务端持有密钥没有意义；需要加密应放在文件系统层 |
| 上传内容类型检查 | 服务只做存储与转发，不对内容负责；下载时统一加 `Content-Disposition` 与 `nosniff` |
| 速率限制的分布式共享 | 单实例部署，进程内令牌桶够用；多实例需换外部存储 |
| 审计日志防篡改 | 需要外部不可变日志系统 |

## 已知风险

1. **百度适配器依赖非公开接口**。Cookie 失效、接口变更、风控封禁都可能导致不可用。这是 ToS 风险，不是安全漏洞，但会直接影响可用性。
2. **限流是进程内的**。重启清零，多实例不共享。它只抬高暴力破解成本，不是可靠的防护。
3. **分享链接就是凭据**。链接泄露等于内容泄露，没有额外的访问控制。敏感内容应设提取码与有效期。
4. **提取码强度取决于创建者**。服务不强制长度或复杂度。
